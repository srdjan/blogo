## Behavior rule

The whole phase preserves behavior: every route keeps its status, headers,
and body. The Phase 2 route tests in `tests/http/routes_test.tsx` and
`tests/domain/static_builder_test.ts` judge this. Tests may change only in
how they construct things (a new factory signature, a config object instead
of an environment variable, an error result instead of `ok(null)` in a
double). Do not change any assertion on status, header, or body. In each
commit body, list every test edit and why it is construction-only. The one
exception is C5, which changes the `getPostBySlug` contract; its tests change
as described there.

   It applies the same defaults and the same environment check as today. The
   invalid-environment warning becomes an entry in `warnings` with the same
   text. `createConfig()` becomes the adapter: it calls
   `parseConfig(Deno.env.toObject())`, prints each warning with
   `console.warn`, and returns `config`.
2. Add `site` to `Config`:
   `{ readonly canonicalUrl: string; readonly name: string; readonly twitterHandle: string }`
   with `canonicalUrl = PUBLIC_URL || "https://blogo.timok.deno.net"`,
   `name = "Blogo - Modern Development Blog"`, and
   `twitterHandle = TWITTER_HANDLE || "@blogo_dev"`. Keep
   `server.publicUrl` and its localhost default unchanged.

4. Tests: new `tests/domain/config_test.ts` for `parseConfig`: defaults with

## C4 Route handlers return a View (T5)

Today each handler builds a `Response` itself, and `cachedRender` inspects
the finished `Response` (status, body text) to decide what to cache.

1. In `src/http/view.ts` define the ADT, for example:
   ```ts
   export type View =
     | { readonly kind: "page"; readonly props: LayoutProps; readonly status: 200 | 400 | 500 }
     | { readonly kind: "fragment"; readonly html: string; readonly headers?: Readonly<Record<string, string>> }
     | { readonly kind: "text"; readonly body: string; readonly status: number; readonly contentType?: string }
     | { readonly kind: "xml"; readonly body: string; readonly contentType: string }
     | { readonly kind: "svg"; readonly body: string }
     | { readonly kind: "json"; readonly body: unknown; readonly status: number };
   ```
   Adjust the variants to what the handlers really return. Read every
   handler first and map each current response to one variant, with its
   exact headers. Write the mapping table in the commit body.
2. One `toResponse(view, ctx, deps)` with an exhaustive `switch` on `kind`
   (no `default`; use `assertNever` from `src/lib/result.ts`). A `page`
   gives a fragment for a partial htmx request (the current
   `isHtmxRequest` rule) and the full layout otherwise.
3. The cache wrapper decides on the `View`: it caches only `page` views
   with status 200, keyed as today (`page:` or `htmx:` prefix plus path).
   Cached hits keep the `X-Cache: HIT` header and the other headers they
   have today.
4. Handlers become `(ctx) => Promise<View> | View`. The exported
   `RouteHandlers` stay `(ctx) => Promise<Response>` (wrap each with
   `toResponse`), so `main.ts`, the router, and the static builder do not
   change.
5. Keep the fire-and-forget view-count increment in `post`.

Target: `routes.tsx` (plus `view.ts`) branch count at or below the baseline
47, and no repeated header literals. Report the metrics rows.

Commit: `refactor(http): route handlers return a View rendered in one place`.

### C4 View type (replaces the example)
```ts
export type View =
  | { readonly kind: "page"; readonly props: LayoutProps; readonly status: 200 | 400 | 500 }
  | { readonly kind: "fragment"; readonly html: string; readonly headers: Readonly<Record<string, string>> }
  | { readonly kind: "text"; readonly body: string; readonly status: number; readonly headers?: Readonly<Record<string, string>> }
  | { readonly kind: "xml"; readonly body: string; readonly contentType: string }
  | { readonly kind: "svg"; readonly body: string }
  | { readonly kind: "json"; readonly body: unknown; readonly status: 200 | 503 };
```
- `text` without `headers` is a bare `new Response(body, { status })`. Deno
  then sets `text/plain;charset=UTF-8` (no space), and tests assert that
  exact value. With `headers`, set exactly those headers.
- `fragment` is the searchModal HTML: `Content-Type` plus the given headers
  (`X-Robots-Tag`), no `Cache-Control`, no `Vary`.
- A `page` rendered for a partial htmx request is the page path: it gets
  `Content-Type`, `htmlCacheHeaders`, and `Vary`, like a full page.
- `xml` and `svg` get `Cache-Control: max-age=3600`.
- `json` uses `JSON.stringify(body, null, 2)` with `Content-Type:
  application/json; charset=utf-8`, `Cache-Control: no-cache`, and
  `X-Robots-Tag: noindex, nofollow`.

Mapping (current response, then variant):
- home, about, tags, tagPosts, rssPage, search, post 200: `page` 200.
  Their error pages: `page` 500. tagPosts invalid tag: `page` 400.
- post 404 `Post not found` and 500 `Failed to load post`; rss, rssByTopic,
  sitemap 500; rssByTopic 404 `Topic not found`; ogImagePost 404
  `Not Found` and 500 `Failed to generate OG image`; atprotoVerification
  404 `Not Found`: `text` without headers.
- searchModal 400 and 500: `text` with `Content-Type: text/plain;
  charset=utf-8` and `X-Robots-Tag`. searchModal 200: `fragment` with
  `X-Robots-Tag`.
- robots 200: `text` with `Content-Type: text/plain; charset=utf-8` and
  `Cache-Control: max-age=86400`. atprotoVerification 200: `text` with the
  same content type and `Cache-Control: max-age=3600`.
- rss, rssByTopic, sitemap 200: `xml`. ogImageDefault, ogImagePost 200:
  `svg`. health: `json` 200 or 503.

Cache wrapper facts to keep:
- Wrapped handlers: home, about, tags, tagPosts, post, rssPage. No other
  handler is wrapped.
- Key: `page:` or `htmx:` plus `ctx.pathname` (no query).
- Outside production (TTL 0) the wrapper passes through and adds no
  `X-Cache` header.
- Production HIT: status 200 with exactly `Content-Type`,
  `htmlCacheHeaders`, `Vary`, and `X-Cache: HIT`.
- Production MISS with status 200: the normal headers plus `X-Cache: MISS`.
- Production non-200: passes through with no `X-Cache`.
- The wrapper caches the rendered string for each prefix, so it sits
  between the View and the Response.
- The `post` view-count increment runs only on a MISS today. Keep that.

Branch target: measure `routes.tsx` and `view.ts` together. Report the
combined count, and justify any increase over 47. It is not a hard limit.
