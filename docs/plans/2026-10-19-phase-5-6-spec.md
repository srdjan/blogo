   `"page"` entries are written to `<path>/index.html` (or `/index.html`

### P3 Analytics behind a KV port with a bounded retry (T8)

File: `src/domain/analytics.ts`, new `src/ports/kv.ts`, `src/app/main.ts`.

Today `createAnalyticsService` calls `Deno.openKv()` itself, and
`incrementViewCount` retries `while (!success)` with no limit.

1. `src/ports/kv.ts`: a `ViewCountStore` port with the operations the
   service needs, for example
   `get(slug): Promise<{ value: number | null; versionstamp: string | null }>`,
   `compareAndSet(slug, expected versionstamp, value): Promise<boolean>`,
   `list(): AsyncIterable<{ slug: string; value: number }>`, `close()`.
   Add a Deno KV adapter `openDenoKvViewStore(): Promise<AppResult<ViewCountStore>>`
   with the same error text as today (`Failed to open Deno KV: ...`).
2. `createAnalyticsService(store: ViewCountStore): AnalyticsService` is
   synchronous and has no `Deno.*` call. The increment retries at most 10
   times; after that it returns
   `err` with kind `IOError` and message
   `Failed to increment view count for <slug>: too many conflicts`. Keep the
   other error messages.
3. `main.ts` opens the store through the adapter and passes it in. Keep the
   current startup behavior when opening fails (read `main.ts` first).
4. New `tests/domain/analytics_test.ts` with an in-memory store:
   get of an unknown slug is 0; increment twice gives 2; `getAllViewCounts`
   lists all; a store whose `compareAndSet` always fails gives the
   too-many-conflicts error after exactly 10 attempts; a store that fails
   once and then succeeds gives the incremented value.

Commit: `refactor(analytics): put view counts behind a store port with a retry bound`.
Intent: `refactor`.
