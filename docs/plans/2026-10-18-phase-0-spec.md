## U1 Upgrade htmx 1.9.10 to 4.0.0

Facts from the htmx 4.0.0 source (`dist/htmx.js`):
- htmx 4 sends `HX-Request: true` on every request (line 433).
- It sets `HX-Request-Type` to `"full"` when the target is `document.body`
  or a `select` is used, otherwise `"partial"` (line 578).
- On back and forward navigation it does not restore a snapshot. It sends
  `GET <path>` with `HX-History-Restore-Request: true`, target
  `document.body`, swap `outerSync` (lines 1629-1652). That request has
  `HX-Request-Type: full`.
- Every status swaps except 204 and 304 (default `noSwap`).
- Events use colons: `htmx:before:request`, `htmx:after:swap`,
  `htmx:before:history:restore` (detail `{path, cacheMiss}`). Request and
  swap events carry `detail.ctx` (`ctx.target`, `ctx.request.action`).
  `detail.pathInfo` does not exist.
- Config keys `scrollBehavior`, `scrollIntoViewOnBoost`,
  `getCacheBusterParam`, `refreshOnHistoryMiss` are removed.

## U3 Move asset fingerprinting behind the FileWriter port (B2)

Problem: `fingerprintAssets` in `src/domain/static-builder.ts` (about lines
283-364) calls `walk`, `Deno.readFile`, `Deno.rename`, `Deno.readTextFile`,
and `Deno.writeTextFile` directly. Tests inject a mock writer that writes
nothing to disk, so the step reads the real `_site/` and fails the test
"report counts match generated files". Production is not affected:
`build()` cleans the output directory first.

Changes:
1. `src/ports/writer.ts`: add to `FileWriter` and to `createFileWriter`:
   - `listFiles(dir: string): Promise<AppResult<readonly string[]>>`: all
     file paths under `dir`, recursive, as `${dir}/relative/path`. Use
     `walk` from `jsr:@std/fs@1.0.14/walk` (move the import here from
     `static-builder.ts`).
   - `readBytes(path: string): Promise<AppResult<Uint8Array>>`
   - `readText(path: string): Promise<AppResult<string>>`
   - `rename(from: string, to: string): Promise<AppResult<void>>`
   Each wraps the Deno call in `tryCatch` with an `IOError`, like the
   existing methods.
2. `src/domain/static-builder.ts`: `fingerprintAssets(outputDir, fileWriter,
   logger)` uses only the port. Extract the pure helper
   `fingerprintedPath(relativePath: string, hash: string): string`. Keep the
   hash (first 8 bytes of SHA-256, hex), the extension set, the HTML rewrite,
   the `asset-manifest.json` content, and the log lines unchanged. Replace
   the outer `try/catch` with Result checks: the first port error returns
   `err(createError("IOError", "Asset fingerprinting failed: <message>", ...))`.
   Remove the direct `Deno.*` calls and the `walk` import from this file.
3. Delete the unused `isHtmlRoute` (about line 70).
4. `tests/domain/static_builder_test.ts`:
   - `createMockFileWriter(publicFiles: Record<string, string> = {})` keeps
     an in-memory `written` map. `clean(path)` deletes keys under `path`.
     `copyDir(src, dest)` copies `publicFiles` into `written` as
     `${dest}/${relative}`. `listFiles`, `readBytes`, `readText`, `rename`
     work on the map.
   - Fix "report counts match generated files": delete the unused
     `indexFiles`; assert exact `pages` and `fragments`. The builder writes 11
     fixed entries (5 HTML, 6 non-HTML), 2 per post, 1 per tag; fragments are
     5 + posts + tags. Derive the numbers from the mock content service.
   - New test: public files `css/main.css` and an HTML page that references
     `/css/main.css`. After `build`, `written` has `_site/css/main.<16 hex>.css`
     and no `_site/css/main.css`; the HTML references the new name;
     `_site/asset-manifest.json` maps the old path to the new one.
   - New test: run `build` twice on the same mock writer. The sets of file
     names after each run are equal (no double hash).
   - New test: a writer whose `writeFile` returns an error for one path gives
     a report with that path in `errors` and `pages` one lower.
5. Verify: run `deno test --allow-read --allow-write --allow-env tests/domain/static_builder_test.ts`
   three times in a row. All pass. `git status` shows no new files in the

Commit: `fix(build): route asset fingerprinting through the FileWriter port`.

## U4 Error pages return 5xx and are not cached (B4)

`src/http/routes.tsx`: `renderPage` returns status 200 for error pages.
`cachedRender` caches every 200 response, with TTL `Infinity` when
`DENO_ENV=production`. A transient load failure is then served until restart.

Changes:
1. Give `renderPage` an optional `status` argument (default 200). When it
   is not 200, return the response with that status and the same headers.
2. Every `renderPage` call in a `match` `error:` arm passes 500. The
   invalid tag name branch in `tagPosts` (about line 205) passes 400.
   Search the whole file for `title: "Error - Blog"` and cover each one.
3. `cachedRender` already caches only status 200. Do not change it.
4. htmx 4 swaps 4xx and 5xx responses (U1), so error fragments still show.

Tests in `tests/http/routes_test.tsx`:
- A content service whose `loadPostsMetadataWithViews` returns `err(...)`:
  `home` returns 500 and the body contains `Failed to load posts`.
- With `DENO_ENV=production` set before `createRouteHandlers` (restore the
  old value in `finally`): a failing home, then a succeeding home on the same
  handlers (switch the double's behavior). The second response is 200 with
  the post list, and has no `X-Cache: HIT`.
- `tagPosts` with an invalid tag name returns 400.

Commit: `fix(http): return 5xx for error pages so the HTML cache skips them`.

   `publishAll` counts `skipped`. Update every caller of `publishPost`
